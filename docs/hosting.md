# Hosting contract

Run exactly one application replica and PostgreSQL 18. The Node.js 26.13.1 application image serves the web UI, oRPC API and MCP endpoint, and executes background jobs and investigation runs in process. No Redis or separate worker is required. Replacement must stop the old app before starting the new one. The image's entrypoint is PID 1 during startup migrations, then execs `tini` with the server; the dump-writer backup keys never reach the running server ([deployment § Upgrades, migrations and backups](./deploy.md#upgrades-migrations-and-backups)).

PostgreSQL stores accounts, access settings, package definitions, conversations, turns and job state. `/data` stores bare repositories and detached checkouts; `/backups` is an optional persistent dump volume, enabled with `compose.backup.yaml`. Normal clones/checkouts are cache, but a snapshot created with a one-time SSH key may be irreplaceable without another credential. Back up those bytes separately and retain the encryption keyring outside the database backup.

The application needs outbound access to public Git/SSH hosts, OpenRouter and optionally SMTP/S3/OIDC providers. PostgreSQL stays on a project-private internal network with the alias `cockpit-context-postgres`; it has no host port. The app additionally has an egress network. Each deployment uses a unique Compose project and project-scoped volumes/networks, without `container_name`.

`compose.yaml` publishes no host ports and supports Dokploy Compose domain routing to app port 3000. Plain VPS installs add `compose.vps.yaml` for loopback HTTP behind a TLS proxy. A home machine without a public IP uses the same loopback overlay behind a Cloudflare Tunnel ([deployment § Home server behind a Cloudflare Tunnel](./deploy.md#home-server-behind-a-cloudflare-tunnel)). See [deployment](./deploy.md), [migrations](./schema-migrations.md) and [backup/restore](./backup-restore.md).

## Accepted image-scan findings

Every image scan (CI build, PR checks, release) fails on a fixable HIGH or CRITICAL finding, except the dated, path-scoped entries in `.trivyignore.yaml`, which the workflows pass to Trivy (`trivyignores`). Each entry names exact CVE IDs and one file path, and carries an `expired_at` date: after it the finding fails the scan again.

- **TypeScript 7.0.2 `tsc` (15 HIGH, expires 2027-01-04).** `@typescript/typescript-linux-x64@7.0.2/lib/tsc` is the runtime TypeScript/JavaScript language server (`tsc --lsp --stdio`), not build tooling, so the image keeps it. It is built with Go 1.26.4 and `golang.org/x/text` 0.38.0; the findings are in Go's network, TLS, X.509, ASN.1, XML, HTML-template, URL and `os.Root` code and in `x/text`. The server talks over stdio only, inside the Landlock sandbox with no TCP and a filesystem confined to the checkout ([deployment § Language-server sandbox](./deploy.md#language-server-sandbox)). No stable TypeScript ships on a fixed Go yet: remove the entry and bump TypeScript when a stable release is built with Go ≥ 1.27.3. Any other finding, in any other path, still fails the scan.
